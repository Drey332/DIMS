2. Data Model Expansion

Move beyond static incident records.
New schema (shared/fire-intel/schema.ts) should track cause chain metadata:

type FirePrecursor = {
  timestamp: string;
  location: GeoJSON;
  sensorData: {
    gasConcentration: number;
    pressureVariance: number;
    temperatureDelta: number;
  };
  humanFactors: {
    fatigueIndex: number;
    stressLevel: number;
    deviationFromSOP: number;
  };
  environmental: {
    windSpeed: number;
    humidity: number;
    seaState: number;
  };
  barrierIntegrity: {
    valveHealth: number;
    pumpStatus: number;
    electricalIsolation: number;
  };
  contextSnapshot: string; // narrative for AI reasoning
};

Each precursor forms a “sentence” in the story leading to an incident.
This gives the model narrative context for why and how an incident formed.

3. Machine Learning Architecture

🔹 Multi-Stream Temporal Graph Model

A Graph Neural Network (GNN) that models interdependencies between:
	•	Equipment nodes
	•	Human nodes
	•	Environmental nodes

Each edge captures causal relationships (e.g., high fatigue → delayed valve closure → gas buildup).

Why investors love this: You’re not just doing ML — you’re doing causal AI that learns why disasters happen, not just when.

4. Training Data Pipeline

Source	Data Type	Purpose

➡ Each event forms a timeline vector labeled by outcome (safe, near-miss, incident).
The model learns to detect trajectory divergence — the moment operations start mirroring a known disaster curve.

⸻

5. Predictive Intelligence Engine

Risk Classification

Uses a continuous Fire Likelihood Index (FLI):

FLI < 0.3 → Normal  
0.3 ≤ FLI < 0.6 → Anomaly emerging  
0.6 ≤ FLI < 0.8 → Near-critical (trigger partial shutdowns)  
≥ 0.8 → Critical risk (pre-incident intervention)  

Explainability Layer

Natural language output:

“FLI increased from 0.42 → 0.79 in 30 minutes.
Pattern resembles Deepwater Horizon’s pre-ignition phase: rising BOP pressure + missed valve test.
Recommend immediate inspection of valve group B14.”

(This makes the AI auditable and regulator-friendly.)
